# Autonomous bootstrap contract — Product-to-Market

## Bootstrap state: INITIALIZED, NOT RUNNING CONTINUOUSLY
This document is a resumable protocol, not an installed autonomous agent. Each session acts with tools currently connected and available; no background execution without a scheduled task.

## Pass 1 — Verified portfolio discovery
- Dynamically enumerate accessible repositories and recent issue/PR activity; start with AION, vivim-harness, VIVIM, Product_Hub, VOMEGA, zcode-pocket and any currently maintained user-facing prototypes.
- Group by **user product**, **shared platform component**, **enabler/tool**, **research**, **inactive**. Do not treat repo names as product proof.
- Extract the latest actual user-facing paths, demos, deploy URLs, README claims, test receipts and blockers with source refs and timestamps.
- Check AION canonical root AGENTS.md and VIVIM Harness current README first. Do not confuse migration in progress with completed centralization.

## Pass 2 — Product packaging
- Clarify 3 candidate launch wedges: (a) Capture Studio read/capture and navigate; (b) native multi-turn assistant via a bound provider session; (c) phone-friendly AI command/intake hub. Score all on external-user friction and maturity.
- Evaluate feasible combined platform composition: shared identity / navigation / storage / instrumentation where actually reusable, without merging repos indiscriminately.
- Write one crisp beta promise and one real end-to-end external-user journey.
- Explicitly decide what is excluded from beta.

## Pass 3 — Shipping execution
- Choose a single first product and beta gate: URL reachable by external tester; minimal onboarding and access control; no dependency on owner's browser/account; one tested useful journey; failure handling; basic feedback capture; simple rollback.
- Name the **smallest verified blocker**. Work on it in source if safe and in scope, otherwise open one actionable issue pointing at exact repo and file.
- List a second product only as next after beta, not another simultaneous launch.

## Verification / anti-fiction
Classify each item as VERIFIED LIVE, VERIFIED CODE, TEST-ONLY, REPORTED, PROPOSED, or UNKNOWN. Distinguish simulated browser runs from actual authorized webapp execution and friend-tested acceptance. Never invent market demand or completion.
No automatic schedule, deployment, local service or Windows installation is implied by this document.
