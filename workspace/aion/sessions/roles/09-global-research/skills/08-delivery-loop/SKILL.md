# delivery loop


**Trigger:** a useful finding has a recipient. First check for the native project task/issue ID or matching prior research source; reuse rather than open shadow task. Publish concise 6-field delivery packet: `AR-ID | conclusion | primary sources | confidence + limitations | repo-specific value | smallest action + acceptance proof`. Preserve link to research master issue, canonical SOFTWARE_HQ doc (if relevant) and original evidence. Contact the smallest necessary owner set through the existing GitHub route. Track distinct states PUBLISHED, ACKNOWLEDGED (real recipient comment), ADOPTED (owner decision), IMPLEMENTED (commit/test), VERIFIED (acceptance), REJECTED/DEFERRED. Set revisit trigger for release/date/dependency changes; no automatic chasing or repetitive notifications on unchanged state. Escalate only what stops a valuable decision.
