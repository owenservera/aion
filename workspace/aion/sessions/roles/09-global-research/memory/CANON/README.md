## Durable operating decisions

- Research is the **one global evidence-to-decision function**: discover, dedupe, verify, synthesize and route external facts so the relevant project owner can act. Keep **one [research issue #30](https://github.com/owenservera/aion/issues/30)** for intake and delivery; do not create a competing research queue, provider registry, corpus, GPM board or workflow service. [Role charter](../../BOOTSTRAP.md).
- **Custody and accountability remain separate:** original authored technical proposals → Intake 07 ([#20](https://github.com/owenservera/aion/issues/20)); durable technical docs → SOFTWARE_HQ; donor custody → Harvest; prototype prioritization → Planning; implementation and actual live acceptance → Development/Windows; cross-portfolio orchestration → GPM. Research retains evidence interpretation and cross-project relevance, not ownership of those sources. [Repo governance](https://github.com/owenservera/aion/blob/main/REPOSITORY-GOVERNANCE.md).
- **Observed evidence is not equivalent to claimed capability.** A vendor document, benchmark, research comment, offline unit test, merged PR, locally installed binary, authorized effect, independently verified acceptance and target-agent ACK are *different* maturity levels. Establish date, original source/author, version, rights, counterevidence, exact project/entitlement fit and next falsifiable test. Never call GitHub publication a notification or another agent's ACK. [Role instructions](../../AGENTS.md).
- AION's **Windows local system controls actual host work**; remote GitHub `main` is authoritative shared source, not telemetry for local checkout/browser/grants. Don't claim host tests or machine synchronization from remote readback. No credential/private transcript replication, unsupported account operation, Playwright/Puppeteer, Slack dependency, or guessed NotebookLM integration. [Root instructions](https://github.com/owenservera/aion/blob/main/AGENTS.md).
- **Separate the two legitimate research purposes:** unblock a specific AION P01–P03 dependency *when external evidence can actually help*; and explore owner-requested **personal low-friction programmable visualization** as independent one-person research, not a corporate AION milestone. [Owner-scoped research goal](https://github.com/owenservera/aion/issues/30#issuecomment-6313116067).

## Lessons from observed friction and the better defaults

1. **Old narrative mistaken for current truth.** Role 09 SITREP once listed three issue #30 comments and pre-merge P3/P4 source state; subsequently issue #30 acquired a fourth comment and [PR #62](https://github.com/owenservera/aion/pull/62) merged source. **Instead:** read current facts first, mark older snapshots as historical, update [Immediate](../Immediate/README.md), and summarize only material deltas; avoid ever-growing redundant chronological status.
2. **Over-scanning in place of delivery.** Broad provider/donor sweeps can consume effort while P01 registration and live I1 evidence still define the critical path. **Instead:** identify the *one external unknown* whose answer will change implementation, cost or safety; defer curiosity that does not alter the current decision. No new artificial prerequisite or ceremony. [Planning priorities](../../../02-long-term-planning-alignment/TASKS.md).
3. **Duplication creates contradictions.** Research issues, SITREP, shared intelligence, Harvest exchange and project desks are not interchangeable authoritative stores. **Instead:** create each source/evidence record once, and store only a pointer plus role-specific judgment in other places. Keep [ACTIVE.md](https://github.com/owenservera/aion/blob/main/workspace/aion/shared/agent-communications/intelligence/ACTIVE.md) a directory, not a parallel report.
4. **Unwarranted completeness and status claims.** GitHub list query returned 100 then zero; a separate search exposed 193 matches. That is bounded query evidence, *not* complete authorization/portfolio discovery. An enabled task or issue comment is not a delivered research report or receipt. **Instead:** name observed scope, source, time and unverified remainder; revalidate when scope matters. [Research workspace](../../WORKSPACE.md), [schedule contract](../../SCHEDULES.md).
5. **Needless owner intervention.** Repeatedly requesting directions for already-scoped research, handing back long undocumented lists or suggesting installations before a small pilot contradicts the owner's autonomy/low-friction objective. **Instead:** inspect existing context, perform reversible scoped work now, produce one sourced decision packet or small realistic test, verify results, and ask only when access, irreversible action or a true choice requires it.

**Maintenance:** Promote only durable, evidence-supported lessons. Correct or retire invalid ones as authority changes; do not accumulate personal lore. A normal no-change interaction does not require a GitHub edit.
