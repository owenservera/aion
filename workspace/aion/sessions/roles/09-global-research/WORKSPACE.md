# AION RESEARCH | One knowledge supply chain

## Architecture
```
One front door: owner message / URL / file / video / podcast / article /
science question / project research need / authorized Google-source discovery
    -> classify & source-protect -> dedupe against canonical issue/known research
    -> effort/value/evidence triage -> select specialist skills and tools
    -> research (primary docs, scientific evidence, Context7, media)
    -> synthesize with contradictions and confidence
    -> compare ALL relevant discovered repositories + project dependencies
    -> publish canonical knowledge to SOFTWARE_HQ or existing owner location
    -> target native project task(s) and verifiable human/agent acknowledgment
    -> check implementation evidence -> close / revisit when triggered
```

## Data placement: no second database
- **Control plane:** this role's BOOTSTRAP, SITREP, skills, tool capabilities and schedule contracts.
- **One intake queue:** a single pinned AION RESEARCH GitHub issue, comments for new candidate submissions and status; stable ID from source canonical URL/DOI + origin, or immutable user-input hash when no link. When volume requires it, link project-native issues rather than invent a parallel tracker.
- **Evidence/source custody:** link publisher original + captured excerpt/metadata; Role 07 retains any proposal RAW; existing project evidence stays in its original repo. Do not mirror large files, copyrighted material or private Gmail contents to public repos.
- **Knowledge output:** SOFTWARE_HQ documentation architecture when appropriate; otherwise the original governing project. NotebookLM is a *working analysis surface*, not authoritative knowledge storage or intake queue.
- **Task execution:** native repository issues/project boards, coordinated by GPM, with back-links to research findings. Single source link for each conclusion.

## Intake classes and auto-routing
1. `RESEARCH_Q`: question/hypothesis -> direct investigation, review.
2. `LINK_MEDIA`: YouTube/podcast/article -> inspect actual available content, dated source, context/claims, classify interests.
3. `DOCS_INTEL`: SDK/standards/Context7 -> upstream versioned authoritative docs, persist extraction to SOFTWARE_HQ under its rules.
4. `TECH_SCOUT`: emerging tool/model/architecture -> applicability map, maturity and adoption trigger.
5. `PROJECT_REQUEST`: originating repo + requirements -> cross-repo search and targeted findings.
6. `PROPOSAL_RAW`: route to existing Role 07 custody, then research questions here; never duplicate RAW.
7. `GOOGLE_SOURCE`: scoped Drive/Gmail/Calendar/Contacts investigation under connector permissions, no unapproved external sharing.

## Prioritization, not a manufactured KPI
P0 user explicitly needs a decision now / project blocked by missing external knowledge. P1 actionable evidence with cross-project leverage or expensive mistakes avoided. P2 relevant strategic scouting. P3 curiosity/archive. Evaluate expected upside x likelihood x cross-project reach / cost and time sensitivity; state assumptions, no fake numeric ROI. Auto-handle short P1s, batch P2s weekly, suppress unchanged P3s.

## Handoffs
Packet = research ID + 1-line finding + source/permalink + known limits/confidence + why *this specific repo* benefits + smallest suggested owner action + acceptance/evidence request. Send only to affected owners; no mass fan-out. Use GitHub-native issue/commit links; request actual ACK, not implicit chat delivery.

## Quality gates
- Verified primary URL and publication/version date; author/publisher and rights.
- At least one independent countercheck for consequential/high-impact claims where feasible.
- Explicit negative or contradictory result when found.
- Repro recipe/limitations for empirical claims; distinguish hypothetical applicability.
- Source-faithful summary, cross-project effect and concrete destination.
- Closure requires a real target issue/receipt and current status. Respect project authority and privacy.

## Proactivity
Daily: deduped research intake and source deltas; do most work quietly and report top 3 changes only. Weekly: portfolio-wide frontier scan plus stale handoff review; note unknown coverage. On-demand: user just drops a URL, voice-note content, paper, topic or file; process with minimal questions. Escalate only credential setup, permissions, external sharing, irreversible expense or truly ambiguous ownership.
