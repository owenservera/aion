## Critical protocol facts for every experiment

1. **There are at least two distinct streams:** page-observer change notifications (metadata/hints) versus fetched validated event/snapshot *content*. A green hint/ping does not prove text arrived at the CLI. A working API SSE response is not a subscription to an existing browser thread.
2. **Identity is a first-class boundary:** authenticated lane registration, exact tab + conversation binding, page/stream epoch and message ID/revision. URL alone does not prove account identity. A manual account switch in the registered lane is an acknowledged limitation of current source and deserves a negative test / explicit re-registration workflow.
3. **Best-effort sampling ≠ lossless server event ingestion:** DOM observer sampling is capped; page can remount; older DOM history can be absent; message identity can be provisional. Require gap/coverage signaling, authoritative replay/snapshot reconciliation and a recoverable cursor before asserting reliability.
4. **Chrome MV3 lifecycle changes matter:** Chrome documents service-worker idling/revival and native-messaging strong keepalive while connected; a port still can disconnect. Opening an ordinary long-lived port alone does not mean indefinite service-worker life. [Official lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).
5. **Capture only necessary diagnostics:** while experimenting, store route ID fingerprints/status codes/cursor counts/timestamps and source hashes, not cookies, emails, account IDs, full conversation text or private URLs in GitHub. The local PC can hold explicitly authorized private content in owner-controlled storage; no silent onward publishing.
6. **The lab is an investigation, not a deployment claim:** no change to `manifest.json`, production observer, existing Bus or local installed processes is authorized by creating this report. The only next action is [a focused real Windows measurement](EXPERIMENTS.md), performed by a capable authorized native executor.

## Research conclusions and re-evaluation triggers

**Conclusion, confidence HIGH for documentation/source architecture:** reuse the existing DOM → extension → native IPC path for ChatGPT first. The highest information value now comes from a read-only, exact-thread *live experiment*, not broader vendor browsing. **Confidence UNKNOWN** for current installed Chrome/host account-registration and live stream effectiveness.

Revisit CDP/UIA or alternate transport only if the test isolates a specific DOM, access, rendering, transport, latency or recovery failure not cheaply fixable at the existing seam. For a second website, independently re-evaluate login authority, page-change observation and safe selectors; retain the generic receipt/coverage framework without assuming ChatGPT's protocol transfers.
