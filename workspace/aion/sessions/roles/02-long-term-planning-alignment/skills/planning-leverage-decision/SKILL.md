# Planning Leverage Decision

## Use when
A new donor, staged PACK, Research finding or agent proposal might change **AION's next deliverable**, bottleneck, dependency or total Development effort. Not for donor-source excavation, staging code, implementing adapters or overriding Development's source choice.

## Repeatable decision
1. Read Planning `memory/Immediate/README.md` and `TASKS.md`; identify the **currently evidenced** critical-path obstacle. Separate an observed defect from a prediction.
2. Read the specific existing [Harvest source](../../../../../ops/chrome-relay/harvest/START-HERE.md), `EXCHANGE.jsonl` topic, Integration Manager pack status and Developer-selected seam. Ask Harvest/Research for new evidence only if a key fact is absent and consequential; do not launch a full matrix rescan.
3. Write one sentence identifying **what working implementation/time this reuse would replace**. If the claim is only vocabulary overlap, staged fixtures, hypothetical capability or 40-command completeness, do not elevate it into a P0 gate.
4. Decide: **ADOPT PRIORITY NOW** only with a real blocker or sizeable substantiated shortcut and a Development-owned insertion/test seam; **DEFER** when the trigger is later (I2 correlation, future commands, attachments); **REJECT** on duplicated capability, unsafe effect defaults, incompatible license/contracts, or negative value.
5. Return concise evidence, owner, what outcome would be affected and **what would falsify this recommendation**. Planning owns priority; Development owns implementation/acceptance; Integration Manager stages *only after selection*.
6. If a material decision changed, update the existing Planning `TASKS.md`/`SITREP.md` and their source links. Leave technical NEED/OFFER records in the sole Harvest EXCHANGE and cross-project research in Research.

## Important current interpretation
PACK-04/06 are conditional I1 help; PACK-03/08 are relevant around real I2 correlation; PACK-05 command breadth and PACK-07 attachment integrity are later product slices. **These are dated decisions, not permanent skill rules.** Re-evaluate them against latest evidence.

## Boundaries
No automatic GitHub issue assignment or agent dispatch, no product Send, no extra approvals, no fabricated savings numbers. Reuse Toolsmith's verification-proof, Research's evidence-assessment and Harvest's own pinned-source reference material. Source-inspected or staged ≠ integrated ≠ tested ≠ live accepted.
