# Webapp-Native Harness CANON — durable lessons

- Capture Studio owns the one browser action/capture/recording path. Never create a competing sender or duplicate Bus.
- Standardize agent interpretation and evidence-linked behavior, not the webapps' native response schemas.
- ChatGPT/Claude webapp DOM, internal network and public model APIs are **distinct data sources**; observed internal endpoints must not become authenticated replay dispatch.
- Browser tab != conversation != provider task != AION harness run.
- Message text/order/title cannot establish durable message/thread ID. Missing native identity is **unknown**.
- Reply DOM, network terminal, page readiness, capture accepted and goal fulfilled are different states.
- Native artifacts, code/writing blocks, citations, tool activity and visible thinking summaries are not plain answer text. No hidden reasoning access claims.
- Preserve raw and unmatched native structure plus version/branch/generation; projections are lossy views with explicit loss markers.
- An uncertain external effect must not be silently repeated; source freshness must prove the current post-send turn, not old matching history.
- Research status/source documents and GitHub commits never prove the owner's Windows runtime, an installed skill, a live provider reply or an agent dispatch.
- User prefers Z.ai executor autonomy: give it baseline, objectives and acceptance; let it choose engineering path.
