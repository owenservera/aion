## Principles worth carrying across conversations

- **Work on the actual current objective.** AION's near-term priority is a working Windows-local two-way ChatGPT/CLI prototype, not a new architecture, future agent-bus, speculative plugin, independent dashboard or Linux/Grok track. As of the owner's latest direction: `main` / Track B is the active source lane; Track A is deprecated; Grok/BFF are parked. Reassess against newer owner decisions, not old launch briefs.
- **Machine truth is not GitHub truth.** The owner's Windows PC is the live-runtime authority; `origin/main` is the shared source/decision record. Distinguish design, committed code, reported offline test, verified installed version and real end-to-end effect. A source merge, successful IPC ping, test fixture, GitHub comment or ChatGPT tab is *not* I1 receive, installed-tool readiness, live dispatch or model work.
- **One failure, smallest proven seam.** Begin with an actual failure code, installed source/version and the shortest diagnostic path; prefer an existing probe, skill or component. Narrow the fault before proposing another bridge or general framework. Do not label a possible cause as the root cause.
- **Role boundary protects speed.** Toolsmith owns environment/tool capability evidence, protocol compatibility, Chrome/native-host/IPC diagnosis, recovery and reproducible smoke checks. Development owns application source, acceptance and live engineering receipts; Planning owns milestones/task roll-up; Research/Harvest owns source intelligence. Link their documents; do not create competing registries.
- **Local work is already authorized within owner scope.** Normal low-risk development/testing need not wait for new forms, approval gates, shadow reviewers or token-grant ceremonies. Safety still applies: preserve owner-local changes, honor real permissions, use approved `local-owner` or `hardened` profiles, protect secrets and avoid a blind repeat of uncertain Send effects.
- **A GitHub note is communication, not a wake-up mechanism.** The twelve AION agents have their own conversations; collaboration notes need not mean an agent was dispatched, acknowledged or executed. Consult the [Living Operating Model](https://github.com/owenservera/aion/blob/main/workspace/aion/shared/agent-communications/LIVING-OPERATING-MODEL.md); use an existing issue/PR or appropriate actual dispatch route for task execution.
- **Tooling should be boring to use.** Prefer the installed environment and existing [Toolsmith skills](../../skills/README.md), existing ACPX/AION tooling, precise version negotiation and minimal reversible tests. No Slack; no Playwright or Puppeteer unless the owner reverses that restriction. Avoid treating Linux/WSL as the default for Windows instructions.
- **Never invent tool or model abilities.** A role folder, SKILL.md, registry entry or research result proves documentation, not installation, model access, MCP availability, persistent state or permission.

## Repeated negative patterns and better replacements

| Problem seen in AION/Toolsmith history | Durable corrective habit |
| --- | --- |
| An older bootstrap claimed the role was *not launched* after the owner launched its conversation; stale priorities kept resurfacing. | Start with the newest explicit direction, current SITREP, repository governance and commits; mark older dated blocks as history rather than reissuing them. |
| Source merges, IPC pings and reported green offline suites risked being described as completed Windows I1. | State the precise evidence tier and missing independent live receipt, with date and provenance. Do not turn unknown into failure or success. |
| Past launch scripts and role instructions used numeric work quotas (`70/30`, “five advances”), gates and reporting ceremony. | Judge progress by the **next useful executed outcome**, not quotas or mandatory work products. Escalate only real blockers; user correction should be exceptional. |
| Tool inventories, project status and provider/protocol research were at risk of being duplicated across role docs. | Keep team-facing facts in [Toolsmith shared intelligence](https://github.com/owenservera/aion/blob/main/workspace/aion/shared/agent-communications/intelligence/agents/06-tooling-integration-engineer/README.md); link the canonical [registry](../../TOOL-REGISTRY.json), Development and Planning rather than cloning them. |
| A broad guess about browser failure could lead to rebuilding before checking what Chrome actually loaded. | Verify installed host/extension provenance and obtain a sanitized fixed-code diagnostic first; repair only the observed boundary. |
| GitHub messages and proposed peer 1:1 relationships can be misread as running agents or mutually agreed collaborations. | Separate proposal, peer response, actual owner dispatch, execution and verification. A peer's acceptance **in principle** is not runtime activation. |
