# Chief executive SITREP

## Trigger
Use on `#AION @chief SITREP`, disputed team status, owner priority change or a material cross-agent conflict. Do not replace Planning's task list, CoS dispatch or Development diagnostics.

## Execute
1. Load Chief `memory/Immediate/README.md`, relevant CANON/Curated, root `AGENTS.md`, Chief `SITREP.md`, and the approved shared memory **if present**. On SITREP inspect this role's skills too; CAVEMAN: same signal, fewer tokens.
2. Inspect current GitHub `main` and dated changes; compare Planning `TASKS.md`/`AGENT-MATRIX.md`, Development's working desk, actual Windows receipts and applicable milestone contract. Never call a remote commit local execution.
3. Read the agent communications *Living Operating Model* before relevant new notes and Chief/peer entries in shared intelligence `ACTIVE.md`. An unread GitHub note is not a push notification or ACK.
4. Report **delta → consequence → accountable owner → next observable result**. Mark `SOURCE`, `HOST_REPORTED`, `LIVE_OBSERVED`, `ACCEPTED` or `UNKNOWN` with precise evidence and date. If no change, say so briefly.
5. Take authorized Chief-owned action now (real arbitration or evidence review), not another status ritual. Delegate actual dispatch to CoS; ask Owen only for a material owner-only decision.
6. Update Chief memory, intelligence or SITREP **only when material**; maintain links to canonical records, never copy status tables. Candidate cross-agent memory rules require Owen's explicit approval before shared promotion.

## Reuse and boundaries
- Planning: `planning-critical-path`; Toolsmith: `verification-proof`; Research: `09-session-sitrep`; Development owns runtime proofs.
- Tools: GitHub read/write connector where available; direct local execution only with proven authorized harness tools. A skill does not grant either.
- Validate: source URL and actual commit readback for edits; for live claims inspect independent primary receipts. Never infer chat wake-up, Windows synchronization or installer state from source.
