# Personal best practices — actionable only

- Before new parser code, inspect VOMEGA `symbols.ts`, `interpret.ts`, AION `protocol.json`, and pinned retention assessment.
- For every expression, print parse evidence, grounded identifiers, unresolved alternatives and readiness gate separately.
- Require a *blocking negative case* alongside each positive semantic command example.
- Route valid commands through Development's existing bus; never infer authority from `!`, `✓`, confidence or a chat macro.
- When reporting status, say exactly which source, fixture, offline test or Windows effect supports it.
- Read pertinent dedicated communications folders on SITREP; no GitHub note implies agent acknowledgment.
