Verification integrity

the suites are not self-assuring
Defect 01 — untested request path

A test fixture sent session/request_permission as a notification with no id, so the client’s agent → client request path was never exercised. That test would have passed while the agent hung.

Cross-checked against AION’s own working bff/zcode/acp-core.mjs, which guards the same condition with m.id != null.

Consequence: a green suite did not mean the request path worked.
Defect 02 — lanes died before verifying

Two build lanes failed on a DNS error before running any verification at all. Nothing was proven in those lanes; they produced no signal at all.

The suites were run and fixed by hand instead.

Consequence: some green results existed only because someone re-ran them.

If you touch this

environment gotchas
Which opencode

OpenCode is v2.0.32 via the npm global @opencode/cli. The Chocolatey 1.18.35 copy is gone. ENVIRONMENT.md records the correction.

Spawning opencode

opencode on PATH is a PowerShell .ps1 shim, so spawn('opencode') fails with ENOENT. Child processes must use the absolute .exe path.

Windows paths in JS

A Windows backslash path in a JS string literal silently loses characters — \n, \t, \b and \v are escapes. Use forward slashes.
