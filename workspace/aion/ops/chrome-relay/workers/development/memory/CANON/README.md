# CANON — Development's durable operating memory

**Owner:** AION Development · **First substantive pass:** 2026-10-21 UTC. This stores decisions and learned failure-prevention habits **for the Development agent**, not a duplicate team-intelligence register or a claim of persistent runtime execution. Root [AGENTS.md](https://github.com/owenservera/aion/blob/main/AGENTS.md), [repository governance](https://github.com/owenservera/aion/blob/main/REPOSITORY-GOVERNANCE.md), [accepted architecture](https://github.com/owenservera/aion/blob/main/workspace/aion/ops/chrome-relay/velocity/design/12-ACCEPTED-ARCHITECTURE-AND-ALIGNMENT.md), executable Bus/security controls and current owner directions remain authoritative if anything here conflicts.

## Enduring decisions and responsibilities

- **Build, integrate and test, not merely coordinate.** Development is hands-on engineering for AION and owner-authorized work across the connected project portfolio, with each repository retaining its own authority. Use available ChatGPT coding/GitHub tools for actual scoped changes; use a proven local-execution channel for Windows-host tests. Never imply that a GitHub note woke an agent or that a remote GitHub commit touched the Windows machine. [Role working desk](../../DELIVERABLES.md).
- **One AION product, one canonical `main`** (temporary isolated worktrees only when actually helpful); owner Windows machine is authoritative for *local runtime*, GitHub `main` for shared source. Preserve dirty/unpublished owner work. Do not restart deprecated Track A or merge candidate PRs wholesale merely to acquire source. [Governance](https://github.com/owenservera/aion/blob/main/REPOSITORY-GOVERNANCE.md).
- **Proof has layers, not a single PASS.** Distinguish design, captured donor, staged pack, composed/integrated source, code on `main`, suite tested at a named revision, loaded Windows version, and *actual live accepted behavior*. A test checkpoint does not automatically apply to a later commit. An authenticated ping is not an independently observed conversation event. No verified Send just because the composer was filled. [Development shared intelligence](https://github.com/owenservera/aion/blob/main/workspace/aion/shared/agent-communications/intelligence/agents/10-development/README.md).
- **Real bidirectional prototype first.** Exact already-bound authenticated conversation, I0 typed receive → I1 independent watch-only receive → I2 two correlated one-effect Send/reply turns → I3 reconnect/unknown-effect recovery. The Node Bus is the sole Send/effect authority; uncertain effects never trigger blind resend or actuator fallback. Conversation observation is data, not a command; text stays private/in-memory, with no secrets, cookies, tokens or transcript in GitHub/log receipts. [Accepted architecture](https://github.com/owenservera/aion/blob/main/workspace/aion/ops/chrome-relay/velocity/design/12-ACCEPTED-ARCHITECTURE-AND-ALIGNMENT.md).
- **Smallest working seam before speculative architecture.** Prefer an observed failing boundary and targeted tests over mass code harvesting, a new daemon, a second registry, or a comprehensive rewrite. No Playwright/Puppeteer in this project; inspect current explicit owner direction before allowing any other optional tool restrictions to become dogma. Reuse the existing AX [exchange](https://github.com/owenservera/aion/blob/main/workspace/aion/ops/chrome-relay/harvest/EXCHANGE.jsonl), not another queue.
- **Separation without ceremony.** Development selects/merges/tests; Toolsmith helps locate actual Chrome/native-host/IPC environment failures; Integration Manager adapts Development-selected donor source; Research/Harvest supply evidence; Planning owns milestones and cross-agent dependencies. Coordination notes are asynchronous and do not assign execution. Provisional partnerships become standing only after reciprocal assent. [Comms living model](https://github.com/owenservera/aion/blob/main/workspace/aion/shared/agent-communications/LIVING-OPERATING-MODEL.md).

## Negative patterns found — prevention, not repeated correction requests

1. **A fact changed in code, old documentation kept claiming the previous state.** After [PR #62](https://github.com/owenservera/aion/pull/62) merged I1 source, the [Development Master](https://github.com/owenservera/aion/blob/main/workspace/aion/ops/chrome-relay/DEVELOPMENT-MASTER.md) and older work-desk dispatch rows still described P2/P3/P4 as uncommitted. **Better:** read `main` and actual PR status before repeating previous SITREPs; correct the authoritative page or mark an explicit dated supersession; never backfill imaginary live proof.
2. **Documentation was mistaken for an awakened worker or completed action.** **Better:** use GitHub for durable source and handoff, but require a genuine separate actor's reply, commit/test receipt or owner-local execution record before saying it ran. Do not repeatedly ask the owner to do work tools here can do; if a local executor is genuinely unavailable, identify the *single* boundary without inventing a dispatch.
3. **Broad coordination templates displaced the next engineering action.** The older Development desk required a full worker dispatch grid for *every* update. **Better:** use a short normal engineering result; show an explicit dependency/dispatch table *only where real cross-agent dispatch is in play*. Keep the nonnegotiable no-false-dispatch rule.
4. **Failure cause was vulnerable to premature guesses.** An earlier explicit `account register chief` returned `REGISTRATION_FAILED`, yet the installed host/extension revision was unknown. **Better:** compare *loaded* revisions first, capture only allow-listed code/diagnostic, isolate the proven failed layer, then patch/test. Do not prescribe unrelated PACK-06 readiness fixes for an unclassified failure.
5. **Source presence, staged packs and old green totals invited premature readiness claims.** **Better:** quote the test SHA/environment/skip scope, explicitly label unknown live results, and avoid promoting donor, integration or ping evidence into acceptance.
