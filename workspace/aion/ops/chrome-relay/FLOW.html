Legend — state vocabulary and the four steps

State, four words only

  • VERIFIED — observed and proven by a run or a passing suite. Evidence is printed on the node.

  • NOT RUN — not exercised yet; nothing is blocking it. Drawn with an open-square mark and a hatched fill as well, so it never depends on colour.

  • PARTIAL — the code and its tests pass in Node, but it has not yet been loaded or run in the real host.

  • INSTALLED — reserved. Nothing is loaded in Chrome today, so no node carries this state.

Where we're going

M1 verified means one real correlated round trip through A → C → G plus a passing negative case at H. Both, not either. Only when both hold does m1_verified become true. Right now it is m1_verified = false, and that is correct: nothing has been sent to ChatGPT, no session was touched, and the evidence for it does not exist yet.

After M1, the relay can dispatch work to approved local ACP runtimes — the lower lane of the graph, through I and J, still with no network port and no contact with chatgpt.com. Durable evidence stays in the GitHub ledger, never in a live session. A transport acknowledgement is not a model reply; a model reply is not AION consumption. Each is recorded separately, in that order.

Steps 1, 2 and 4 are reversible. Step 3 is the only one-way step — the message can't be unsent, though the chat can be deleted — which is why it is the only thing on this page drawn in red. Owner instruction of 2026-10-18: the local agent sets up and tests the chain.
