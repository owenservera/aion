# AION Capture Studio CORE — Negative Space Programming · Pass 1

**Date:** 2026-10-22 · **Scope:** CORE L2–L4/temporal projection · **Status:** SOURCE DELIVERED; native Node/Windows/independent QA pending.

## Purpose

Make genuine incorrect states unrepresentable while preserving the single-PC owner's freedom and complete local capture. This is **not** another authentication layer, approval workflow, privacy filter, policy service, or independent database. It complements the existing local-first owner contract. No Playwright/Puppeteer and no automatic live sends.

The first pass has **one canonical code registry** and two newly enforced rules:

| NSP ID | Negative-space contract | First-pass disposition |
| --- | --- | --- |
| NSP-001 | Raw evidence must not be silently rewritten | DESIGN: existing append-only store remains authoritative; no new enforcement |
| NSP-002 | Inference must not impersonate direct observation | DESIGN: existing temporal lenses already help; unify representations later |
| NSP-003 | Absence is not deletion; one revision cannot simultaneously write and remove one field | **ENFORCED** in `foldRevision` / `RevisionAccumulator`, and isolated in graph building |
| NSP-004 | Incompatible identity signatures cannot occupy one graph node | **ENFORCED** in `buildGraph` preflight and direct `TemporalGraph.upsertEntity` |
| NSP-005 | Unknown external send status cannot justify a silent retry | EXISTING: send-once/idempotency contract; no rewrite |
| NSP-006 | Corrections must preserve their evidence and prior interpretation | DESIGN: L5 specialist owns journaling semantics |
| NSP-007 | A derived claim needs traceable inputs and version metadata | DESIGN: existing receipts; fuller model/coverage classification later |
| NSP-008 | Two writers cannot unknowingly own one browser target | EXISTING: browser lease; no rewrite |

**Do not interpret design/existing labels as eight new runtime gates.**

## Code and machine-readable contract

- `src/core/invariants.mjs` — frozen `NSP_RULES`, `NSP_SCHEMA='capture-studio.nsp/1'`, `InvariantViolation`, `assertInvariant`, `observeInvariant` and `invariantReceipt`.
- `src/intel/history.mjs` — validates atomic revision semantics before touching fields or the journal. A field omitted from an observation continues to retain its previous value. An explicit `removed:[field]` is an intentional deletion. A revision that both supplies `values[field]` and `removed:[field]` throws `NSP-003` **before any state change**; other normal observations are unaffected.
- `src/intel/graph.mjs` — preflights entity EIDs. Conflicting type/scope/method/typed-key signatures for one EID quarantine **all** colliding occurrences, not merely the last writer. Repeated provisional/nonkeyed EIDs are also quarantined. Unaffected entities and edges still materialize. Direct upserts reject incompatible types/typed keys atomically. Explicitly contradictory individual revisions are omitted from the graph without suppressing previous valid revisions.
- `TemporalGraph.toJSON().invariants` includes `{schema,violations}`; `stats.invariantViolations` and `stats.quarantinedEntities` state actual omissions. The stored raw evidence and original entity dataset remain untouched; a conflicted graph is a **partial** projection, not a cleaned-up rewrite.
- `src/replay/derive.mjs` writes `KNOWLEDGE_STATUS.graphIntegrity: 'complete'|'partial'`, `graphInvariantViolations`, and `graphQuarantinedEntities`. The existing `RECEIPT` gains `nsp` summary counts, and a failed derivation with an `InvariantViolation` retains its structured receipt. This is additive: existing CLI/API graph readers can see the new fields via their normal GRAPH response without a new endpoint or service.

**Receipt shape** (illustrative, not an observed live failure):
```json
{
  "schema": "capture-studio.nsp/1",
  "code": "NSP-004",
  "domain": "identity",
  "status": "violated",
  "boundary": "build-graph",
  "disposition": "isolated",
  "reason": "entity-id-collision",
  "source": { "session": "session1", "sid": "stream1", "seq": 17 },
  "entityId": "thing:k:abcdef",
  "count": 2
}
```
Receipts are deterministic metadata **without raw values, prompts, headers, token strings or URLs**; caller input is deliberately whitelisted and sanitized. The graph itself continues to contain the owner's local derived data as before.

## Remaining negative space worth implementing next

1. **NSP-002: epistemic state vocabulary** — reuse/extend L4/L5 `temporal-truth.mjs` observed/partial/unknown/not-yet-observed distinctions; add `inferred` and `contradicted` only where evidence actually supports them. Do not convert unknown into false.
2. **NSP-007: provenance assertion** — when a derived assertion is exposed as verified, require a source locator plus derivation metadata, otherwise label it `unverified`, not zero, false or deleted.
3. **NSP-005/008 existing checks** — connect state/readiness receipts without duplicating send or browser lease machinery.
4. **NSP-001/006 specialist handoff** — preserve raw log immutability and reversible learner journal; CORE wires contracts, L5 owns algorithms.
5. **UI visibility** — optional, nonintrusive partial-result cues and direct jump to supporting source; UI lane owns components. No new modal gate.
6. **Native/local verification** — run focused Node test and full suite with captured source SHA and regression report. No requirement to block normal local development.

## Core design rule

**NSP excludes impossible claims and contradictory mutations, not valid user actions.** A captured credential, long prompt, arbitrary schema, unfamiliar provider, keyless observation or unavailable timestamp is not by itself an error. It stays representable. Only an actual contradiction is isolated or rejected at the smallest meaningful boundary.
