## 1. What changed (single owner: `src/store/versioned.mjs`)
| Defect | Fix |
| --- | --- |
| **B1** CAS bypass | `compareAndSave(name, value, {expectedVersion, changeNote})`: `null` = must not exist; integer 1..9999 = must equal the raw `CURRENT`. `compareAndRollback(name, version, {expectedVersion})`: integer only. `undefined`, missing options, `0`, strings, floats, `NaN`, out of range -> `CAS_EXPECTED_VERSION_INVALID`, thrown before any lock. Mismatch -> `CAS_VERSION_CONFLICT {expected, actual}` inside the lock. **Strict everywhere:** the I1 wrapper, the **factory** (`promote({..., expectedVersion})`: `null` or integer; `rollback(name, v, {expectedVersion})`: integer), and both HTTP routes require the expectation. There is **no** "omitted = current" fallback (an earlier draft had one; it was removed). **ABA closed:** CAS rollback *appends* version N+1 restoring the target (`restoredFrom`), so `CURRENT` only moves forward. The compare uses the raw `CURRENT` integer, never the parsed record, so a corrupt/unselectable head cannot look absent (`STORE_CURRENT_CORRUPT` when `CURRENT` is junk or names a missing file). |
| **B2** lock lifecycle | One per-name lock `<store>/.locks/<lowercase name>.lock` with an owner token (`aion.versioned-store-lock/1`: token, pid, name, op, at). The descriptor is closed immediately and on every path, **always and exactly once** (also after a write/fsync failure); a lock created by a failed acquire is removed (creation-owned); release unlinks only a lock still carrying this operation's token. Primary errors are never replaced (cleanup problems are attached as `releaseError`/`cleanupError`). Committed change + unverified release -> `CAS_LOCK_RELEASE_UNVERIFIED` with `committed:true, committedVersion` (kept through HTTP; the I1 pipeline marks the proposal `promoted`). Locks are never stolen or aged out. A symlinked/junctioned `.locks` directory is refused. **Acquisition under Windows sharing races (found by the independent probe run):** the exclusive create retries `EEXIST` and the transient `EPERM`/`EBUSY`/`EACCES` codes (delete-pending, sharing violations) until `lockWaitMs`, judged by the error code and not by an independent `existsSync` (which flickers). At the deadline: `EEXIST` or an existing lock -> `CAS_LOCKED` (with `cause`/`attempts`); a transient code that never cleared while NO lock exists -> the ORIGINAL error, annotated with `lockAttempts` (a real permission fault is not disguised as busy). Other open errors are never retried. Only the same exclusive create is retried; an existing lock is never deleted, replaced or rewritten. |
| **B3** path traversal | `validateStoreName` (grammar `^[a-z0-9][a-z0-9._-]{0,63}$`, no trailing `.`, no Windows device names) on **every** method; versions are integers 1..9999 (`STORE_VERSION_INVALID`); containment + symlink/junction/realpath refusal for the name directory (`STORE_PATH_ESCAPE`); a record must carry the same `name` (case-insensitive) and integer `version` as the file it is stored in, else `STORE_RECORD_CORRUPT`. HTTP: `STORE_ERROR_STATUS` -> 400/404/409/423 (shared by the hub and the top-level handler). |
| **B4** one owner | `server.mjs` builds ONE `VersionedStore` for the factory and I1. The factory never calls `save`/`rollback`. `createCasVersionedStore` is a thin adapter with no lock/fd code (`lockDir` accepted and ignored). Reserved I1 names `^i1-[0-9a-f]{40}$` are refused/skipped by the factory (`RESERVED_NAMESPACE`). Legacy profile/family `save()`/`rollback()` keep their meaning (pointer move, no migration) but are validated, locked and atomic. |

**Close policy (verified, replaces an earlier retry draft):** `closeSync` is called once per descriptor; if it throws the error is reported as the failure and there is **no retry and no fstat probe**, because after a failed close the descriptor number may already be released and reused, so a second close could close someone else's descriptor. A realistic fault (close completes, then reports an error) is tested; the mock that throws *before* releasing is used only to prove no retry happens.

Test seam: `new VersionedStore(dir, {io, lockWaitMs, lockRetryMs})`; `io` overrides any of `openSync writeFileSync fsyncSync closeSync renameSync unlinkSync readFileSync existsSync readdirSync mkdirSync lstatSync realpathSync`.

Preserved unchanged: intent-binding `r+` flush and its own lock, writable `getAdapter`, actor/journal, `/chat`, provider seeds, data-only `sendPermission:false` learned adapters.

## 5. Behaviour changes operators and reviewers must know
1. `has()/current()/versions()/load()` now **throw** `STORE_NAME_INVALID` for invalid names (previously `has` returned false and reads wandered).
2. Learned-adapter rollback (HTTP `/adapters/learned/{name}/rollback`, `/adapters/intelligence/rollback`, factory API) **appends** a new version restoring the target (response `version` is the new N+1, `restoredFrom` the target). Profile/family rollback is still a pointer move.
3. **Required expectations over HTTP:** `POST /adapters/learned/promote` needs `expectedVersion` (`null` = first create, or the current integer); `POST /adapters/learned/{name}/rollback` and `POST /adapters/intelligence/rollback` need an integer `expectedVersion >= 1`. Existing callers (the demo script) were updated; any external client that omitted the field now gets 400.
4. Factory `list()` and the learned registry view no longer include I1-owned `i1-*` records.
5. Every mutation can wait up to `lockWaitMs` (default 500 ms, synchronous) for a live lock, then fails `CAS_LOCKED` (HTTP 423).
6. A record whose `name`/`version` do not match its file now fails closed (`STORE_RECORD_CORRUPT`) instead of being returned.
7. Built-in profiles/families keep their names; seeding is first-create-only (`compareAndSave(null)`).

## 6. Migration
- On-disk format is backward compatible (`vNNNN.json` + `CURRENT`); CAS rollback adds an optional `restoredFrom`. No data migration.
- New `<store>/.locks/` appears on first mutation. Old I1 locks in `<root>/locks/.cas-*.lock` are no longer used; delete them manually only after confirming no Studio process is running.
- A pre-existing `CURRENT` that is not `^[1-9][0-9]{0,3}$` or names a missing file now fails closed (`STORE_CURRENT_CORRUPT`); repair by hand after review. Hand-edited or copied records whose `name`/`version` fields do not match their file fail closed (`STORE_RECORD_CORRUPT`).
- Orphan versions (crash between version file and `CURRENT` rename) are skipped and never overwritten.

## 8. Operator-guided stale-lock recovery (never automatic)
A crashed holder leaves `<store>/.locks/<name>.lock`; the next mutation fails `CAS_LOCKED`. Do **not** delete it blindly.
1. Stop every Studio/CLI process that uses this data directory (or confirm none is running).
2. Inspect (read-only): in `capture-studio`, `node -e "import('./src/store/versioned.mjs').then(m=>{const s=new m.VersionedStore('<store dir>',{kind:'learned adapter'});console.log(JSON.stringify(s.inspectLock('<name>'),null,2))})"`. `pidAlive:true` -> leave it alone. `pidAlive:false` is only trustworthy after you have confirmed the process is gone (PIDs can be reused).
3. Verify the data first: `current(name)` and the newest `vNNNN.json`; if the interrupted operation was a save, the new version is an orphan (harmless).
4. Release by token: same one-liner with `s.releaseStaleLock('<name>',{token:'<token from step 2>'})`. A wrong/missing token refuses (`CAS_LOCK_TOKEN_MISMATCH`) and removes nothing. A malformed lock cannot be released this way; remove the file manually only after step 1.
5. Retry with a fresh `expectedVersion` read after recovery.
`CAS_LOCK_RELEASE_UNVERIFIED` with `committed:true` means the change **is durable**: do not repeat it; just release the lock as above. These commands were executed against a disposable store and by the killed-holder probe.
