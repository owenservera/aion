### S72-05 — P1, user journey and diagnostic UX: L1 runner does not itself certify the requested full outcome path
**Source:** [`scripts/core-local-handoff.mjs:158–215`](https://github.com/owenservera/aion/blob/3b2ea42f8da3c34f845569dc5a5b96402d8d7dea/workspace/aion/sessions/roles/09-global-research/labs/website-to-local-streaming/capture-studio/scripts/core-local-handoff.mjs#L158-L215) invokes `scripts/live-e2e.mjs --keep`, imports step PASS/FAIL/SKIP and emits QA-format files; its synthetic substeps include recorder, verify, derive and replay/API checks. The source-built live preview in [`src/studio/ui/live.mjs:1–65`](https://github.com/owenservera/aion/blob/3b2ea42f8da3c34f845569dc5a5b96402d8d7dea/workspace/aion/sessions/roles/09-global-research/labs/website-to-local-streaming/capture-studio/src/studio/ui/live.mjs#L1-L65) keeps only a bounded tail, explicitly directing users to saved replay. **Risk:** a full-green L1 runner can coexist with inaccessible/mislinked saved evidence, unclear unknowns, or no usable outcome packet; the QA contract's job-to-be-done remains unproven.

**Smallest proof/correction, owner:** QA adds **checklist/assertion rows in its existing L1 evidence**, no new runner/framework: exact `session_id` -> saved raw/verify -> acceptance label/unknowns -> derived model/entity -> UI permalink with correct SID/seq -> offline Outcome Packet with at least one grounded source locator -> actual user-view/use result. `PASS` only for observed steps; `SKIP` and `PARTIAL` when a downstream component is unavailable.
