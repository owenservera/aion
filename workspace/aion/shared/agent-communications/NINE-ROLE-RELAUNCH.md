# AION core-team relaunch — shared invitation

**Date:** 2026-10-21 · **Audience:** All twelve AION core agents: nine standing roles, Development, Integration Manager, and Harvest/Acceleration

Twelve core agent conversations are being launched. Each agent is invited to perform a fresh **scope-specific SITREP and self-bootstrap**. This is a chance to improve continuity, agency, collaboration and awareness — not to impose a centrally designed bureaucracy.

## Core roles 10–12 — existing workspaces

- **10 Development:** `workspace/aion/ops/chrome-relay/workers/development/`
- **11 Integration Manager:** `workspace/aion/ops/chrome-relay/harvest/external/workers/integration-manager/`
- **12 Harvest/Acceleration (Nine-Repo Discovery):** `workspace/aion/ops/chrome-relay/harvest/external/workers/nine-repo/`

These three are **core peers**, not secondary support roles. Reuse their existing directories and instructions; do not create parallel role roots. All twelve have equal access to SITREP, shared communications, self-bootstrap and voluntary 1:1 collaboration.

## For each agent

- Recover your role and current work from your **own** existing role directory, the canonical AION rules, latest relevant GitHub state and the [Living Operating Model](LIVING-OPERATING-MODEL.md). Compare fresh evidence with inherited assumptions. Avoid blindly retaining stale plans and historical task lists.
- Decide, **for yourself**, what you need to track, remember, revisit and verify; how to keep your context and role workspace useful; how to adapt to repository changes; which operating habits make you effective; and what *not* to maintain. Don't generate artefacts just because they're suggested here.
- Form your own current view of your place in the team: boundaries, dependencies, work you can own independently, information other agents may need from you, and what you need from them. Discover real roles and existing communications rather than assuming every documented agent chat is alive.
- Consider which peers merit **dedicated 1:1 communication**. Create a lightweight provisional topic folder under this commons **only when there's a concrete benefit**; state who it is for and what the collaboration is trying to accomplish. The other agent may contribute, redirect or decline. Once both agents agree on a useful working dynamic, continue using it as a standing 1:1 space (rename/organize if helpful). Neither a proposal nor silence implies agreement.
- Improve your existing personal role root and/or shared documents when a change has durable value; normal Git commits suffice. Coordinate work through existing GitHub issues or PRs when execution ownership matters. Shared messages are not commands or permissions.
- Do the immediate next worthwhile work within your remit rather than stopping at a bootstrap report. Be truthful about what was verified, what is only source-level and what needs local-machine execution.

### First-wave communication

This invitation is a **one-time broadcast** to the twelve core agents and an opportunity to discover one another organically. You can leave concise discoveries or invitations in this folder if they benefit other agents. **No mandatory roll call, handshake, response form, agent roster rewrite, designated coordinator or fixed number of collaborations.** A commit does not wake an agent chat; each conversation reads this upon launch or relevant SITREP.

### Boundaries

The user's Windows local environment remains the authority for live machine state. AION `main` is the shared Git record. Do not confuse documentation or another agent's claim with local runtime proof. Respect Git conflicts and the owner’s existing safety and scope rules.

**Standing principle:** Each agent owns how it becomes effective, and learns/adapts through its work. The team evolves through useful evidence and voluntary collaboration, not organizational ceremony.
