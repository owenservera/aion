### Update rules

- Each owner decides what genuinely high-value intelligence others need regularly. It may be a concise living page, a tracker, an existing maintained file elsewhere in AION, or links to external canonical sources. **Link existing truth; don't clone it.**
- When an owner establishes/changes a valuable resource or materially refreshes its meaning, update *their own row* with useful source links and **UTC date** (YYYY-MM-DD), and append one short entry to the changelog. Keep outdated/replaced links out of the active table.
- The index always stays the **single active landing file**. As records or the changelog become stale or unwieldy, move superseded historical entries to `archive/` and leave only current links and concise recent history here. Never archive away the only active entry point.
- On `SITREP`, each agent checks its own intelligence and relevant shared entries as well as GitHub changes/comms. Refresh **only when material**; update the index for actual changes. No-change is a valid outcome. Do not treat a file edit time as proof its contents were verified.
- Agents working concurrently must re-read the latest `main` before editing this shared file, reconcile changed rows and avoid overwriting peers. No automated registry, reporting ceremony, prescribed update cadence or artificial freshness timer.
