# Stage 04 — Skills and real local capability

Continue in the same agent conversation after Stage 03. If starting fresh, prefix `#AION @<YOUR-ROLE> SITREP`.

---

**AGENT SKILLS — FIRST PASS + CONTINUOUS CAPABILITY OWNERSHIP**

AION is evolving from conversations toward agents with reusable skills in local harnesses, particularly OpenCode V2, ZCode and appropriate other installed tools.

You own the `skills/` folder inside your existing AION role workspace. Read your `AGENTS.md`, `SITREP.md`, three-tier memory, recent tasks, shared intelligence, team communications and existing skills. Then study the native AION Master Skills Builder:

https://github.com/owenservera/aion/blob/main/.opencode/skills/aion-skill-builder/SKILL.md

Investigate your own **recurring capability gaps**: repeated research, corrections, failed approaches, manual work, tests, procedures and worthwhile automation. Discover what you already have and can reuse across agents. Independently select which skills matter—do not satisfy an arbitrary count or duplicate a functioning peer skill.

Create or improve a practical first pass in your own `skills/` using portable OpenCode V2-style `SKILL.md` and supporting references, scripts, examples or fixtures **only where useful**. Give each skill a clear trigger, verified procedure, tool requirements, stopping conditions, recovery path and test evidence. Use the builder's audit and validation helpers. Prefer deterministic, reusable execution over long instructional documents.

Investigate real harness availability and integration paths. Distinguish *committed source*, *harness discoverability*, *installed runtime tools*, *tested execution* and *actual field success*. GitHub publication alone does not install skills or confer tool permissions on Windows.

Make continuous improvement part of your `SITREP`: identify obsolete, duplicated or missing recurring skills and useful peer reuse, update only when evidence warrants, and keep runtime claims honest. Commit/push real changes.

Close with existing capabilities found, useful skills created/improved, what actually passed validation, what is not yet locally active, and the next highest-value local integration opportunity.

**The goal is agent effectiveness with less user intervention—not a collection of empty skills folders.**
